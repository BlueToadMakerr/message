Bot docs

Quick start

Make a bot in Account → Bots and keep its token. In a chat open Chat options → Add one of my bots…. Your program then calls the API with Authorization: Bearer <token>. The API runs on Firebase, not on the web host, so a host that blocks automated requests doesn't matter.

curl -X POST "$QM_API/send" -H "Authorization: Bearer $QM_TOKEN" -H "Content-Type: application/json" \
  -d '{"chat":"CHAT_ID","text":"Hello!","as":{"name":"Zed","pfp":"https://example.com/z.png"},"src":"Discord"}'

Requests

RequestWhat it does
GET /meThe bot's profile
PATCH /me {name, pfp}The bot changes its own default name / picture (https address)
GET /chatsChats the bot is in
GET /members?chat=Members of a chat
GET /messages?chat=&after=&limit=Messages, oldest first (encrypted ones have encrypted:true and no text)
POST /send {chat, text, as, src, replyTo, file}Post a message. as:{name,pfp} changes the name/picture for that message; src says where it came from
PATCH /message, DELETE /messageEdit / delete the bot's own messages

Who posted what

Every bot message carries botId. With as the chat shows another name and picture, plus a BOT badge with the real bot's name and the src. People can't write these fields, so a bot's identity can't be faked. This is how you link a chat with Discord: post each Discord message as that Discord user.

Webhook

Set an https address on the bot (Edit) and each new message in its chats is POSTed there as {event, bot, chat, message} with X-QM-Signature (HMAC-SHA256 of the body; key = SHA-256 hex of your token). Or poll GET /messages?after=.

Limits and safety

20 posts per 10 seconds, 4000 characters. Bots can't read end-to-end encrypted messages and what they post in an encrypted chat isn't encrypted. The token is the bot's password: only add bots you control, and make a new token if one leaks. A ready-made Discord bridge is in docs/bots/discord_bridge.py.
