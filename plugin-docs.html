Plugin docs

Plugins are small JavaScript programs you write (or import) to change how QuickMessage looks and behaves on your device. They only run while Developer mode is on (Account → Developer) and are stored in this browser only. They never touch other people's devices.

Unsandboxed plugins (extremely dangerous)

⛔ Having a plugin unsandboxed is EXTREMELY DANGEROUS. Normally a plugin runs in a locked box and only gets what its permissions allow. With unsandboxed the lock is removed: the plugin runs with the same power as the site itself. It can read all your messages and encryption keys, send messages as you, read what you type (including passwords), change settings and send everything to anyone. Do not run anything you do not trust completely with this permission, and never turn it on because someone online asked you to. You must type UNSANDBOXED to allow it, and it asks again whenever the plugin changes its permissions.

Inside the plugin, qm.permissions.sandboxed is false and qm.unsafe.window / qm.unsafe.document reach the page. Prefer normal permissions whenever they are enough.

Permission review

When you switch a plugin on, or it asks for new permissions after an edit or update, the Plugins page shows every permission in plain words (most dangerous first, with a risk label) and the plugin stays off until you approve. The Permissions button shows this list at any time. A plugin can read its own list with qm.permissions.list() and qm.permissions.has(name) (no permission needed).

1. Your first plugin in 60 seconds

  1. Account → Developer → turn on Developer mode, then open Plugins.
  2. Press New plugin, pick the Hello (toast) starting point, give it a name and press Save.
  3. Switch the plugin on. You should see a toast saying "Hello from my plugin!".
await qm.toast('Hello from my plugin! Site ' + qm.version, 'success');
qm.on('chat-open', () => qm.toast('You opened a chat'));

Your code is the body of an async function, so you can use await at the top level and return early. The variable qm is the only door to the site.

2. How plugins run

  • Each enabled plugin runs in its own hidden <iframe sandbox="allow-scripts">. Without allow-same-origin it cannot read the site, your login, your messages, cookies, localStorage, IndexedDB or Firebase.
  • A Content-Security-Policy inside the frame blocks every network request unless the plugin declares the network permission (then only https:).
  • Everything a plugin does goes through qm.* calls, which the site checks against the permissions you ticked. A call without the permission fails with an error you can catch.
  • A plugin that throws on start is marked crashed and its error is shown on the Plugins page; other plugins and the site keep working.
  • Plugins run in the app shell, so they work on every page (chat list, chat, account, call). They do not run on a standalone page opened outside the shell.
  • Be careful what you install. Sandboxing protects the site from a plugin, but a plugin you allow to read messages and contact other websites can send what it reads anywhere. Read code before enabling it. The Plugins page labels each permission with its risk.

6. CSS hooks

The site uses CSS variables for colours, so many looks need only a few lines: --accent, --bg, --card, --text, --border. Open Developer mode's { } buttons or the browser's inspector to find class names (.msg, .bubble, .chat-row, .topbar…). Class names are not a stable API: use minSite and test after updates.

7. Examples

Message counter

let n = Number(await qm.storage.get('count')) || 0;
const show = () => qm.panel.set({ title: 'Messages seen', lines: ['Total: ' + n], buttons: ['Reset'] });
show();
qm.on('message', async () => { n++; await qm.storage.set('count', n); show(); });
qm.on('panel-button', async () => { n = 0; await qm.storage.set('count', 0); show(); });

Permissions: panel, messages.

Quick reply buttons

qm.on('chat-open', () => qm.panel.set({ title: 'Quick text', buttons: ['On my way', 'Call you later', 'Thanks!'] }));
qm.on('chat-close', () => qm.panel.hide());
qm.on('panel-button', b => qm.chat.insertText(b.label));

Permissions: panel, chat.

Square bubbles and a red accent

await qm.style.set(`
  :root { --accent: #e11d48; }
  .bubble { border-radius: 4px !important; }
`);

Permission: style.

Joke of the day (network)

const r = await qm.fetch('https://official-joke-api.appspot.com/random_joke');
const j = await r.json();
qm.toast(j.setup + ' ' + j.punchline);

Permissions: network, toast.

Find a message (button that scrolls the chat)

await qm.buttons.add({ id: 'find', where: 'chat', label: 'Find' });
qm.on('button', async b => {
  if (b.id !== 'find') return;
  const text = await qm.ask('Find a message', 'Text to look for');
  if (!text) return;
  const r = await qm.page.scrollUntil({ text, direction: 'up', maxMs: 60000 });
  qm.toast(r.found ? 'Found it' : 'Not found (' + r.reason + ')', r.found ? 'success' : 'error');
});

Permissions: buttons, page, toast.

Extra info in the call stats

const paint = async () => {
  const c = await qm.calls.state();
  let rows = [['In a call', c.joined ? 'yes' : 'no', c.joined ? 'ok' : '']];
  if (c.joined) { const s = await qm.dev.read('call'); rows.push(['Connections', Object.keys(s.links || {}).length]); }
  await qm.dev.addCard('call', { id: 'extra', title: 'Call extras', rows });
};
qm.on('dev-view', paint); qm.on('call-state', paint);

Permissions: devinfo, calls.

Slash commands and a shortcut (1.48.0)

Permissions: commands, keys, send, chat, toast.

await qm.commands.add({ name: 'shrug', description: 'Send a shrug' });
await qm.commands.add({ name: 'time', description: 'Send the time' });
qm.on('command', async c => {
  if (c.name === 'shrug') await qm.chat.send((c.args ? c.args + ' ' : '') + '¯\\_(ツ)_/¯');
  if (c.name === 'time') await qm.chat.send('It is ' + new Date().toLocaleTimeString());
});
await qm.keys.add({ id: 'draft', combo: 'ctrl+shift+d' });
qm.on('key', async () => qm.toast('Draft: ' + (await qm.chat.getText())));

Find your messages and copy them (1.48.0)

Permissions: messages, clipboard, keys, toast.

await qm.keys.add({ id: 'copy', combo: 'ctrl+shift+m' });
qm.on('key', async () => {
  const mine = await qm.messages.find({ fromMe: true, limit: 10 });
  await qm.clipboard.write(mine.map(m => m.text).filter(Boolean).join('\n'));
  qm.toast('Copied ' + mine.length + ' messages');
});

8. Plugin files

Export writes a .qmplugin.json file:

{
  "id": "p3k9x2ab",
  "name": "Message counter",
  "version": "1.2.0",
  "apiVersion": 1,
  "minSite": "1.44.0",
  "updateUrl": "https://example.com/counter.json",
  "description": "Counts messages",
  "author": "You",
  "permissions": ["panel", "messages"],
  "code": "..."
}

Importing a file with the same id (or same name and author) replaces the installed one and keeps it on/off as it was. A new plugin always arrives switched off so you can read its permissions and code first.

9. Versions, outdated warnings, updates

  • Site version (qm.version): shown in Account → Developer and on the Plugins page. The site checks version.json when it opens and every 30 minutes; if a newer version exists a bar offers Reload. From an offline copy the check simply can't reach the site; download a fresh copy when you want to update.
  • Plugin API version (apiVersion): bumped only when something a plugin relies on changes in a way that could break it. A plugin with a lower number than the site is shown as Outdated with a warning (it still runs). A plugin with a higher number, or a minSite newer than the site, is blocked with an explanation until you update the site.
  • When Developer mode starts, a toast warns about every enabled plugin with a problem.
  • Plugin updates: if a plugin has an updateUrl, Check update downloads that JSON ({"version": "1.3.0", "downloadUrl": "https://…"}) and compares versions. It never installs anything by itself; import the new file to update.
  • Version numbers are dotted numbers (1.10.0 is newer than 1.9.2).

10. Limits

  • Code: 200,000 characters. Storage: 100 KB. CSS: 50,000 characters. Panel: 30 lines, 8 buttons.
  • Plugins only run on this device while Developer mode is on. Turning it off stops all of them at once.
  • No access to Firebase, your account's data, other people's devices, or sending messages on your behalf.
  • Plugins are not available in "private server" legacy mode on very old browsers.

11. Troubleshooting

  • Nothing happens: is Developer mode on and the plugin switched on? Look for a red "Crashed" line or the Log on the Plugins page.
  • "Needs the \"x\" permission": tick that permission in the editor and save.
  • fetch fails: add network; the target site must send CORS headers.
  • Style not applied: add !important; the site's own rules can be more specific.
